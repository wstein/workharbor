## Behavior

`Manifest.EffectiveConsoleMode()` resolves an absent preference to `plain` in
old and new manifests. The parsed field stays raw so editors retain the distinction
between an omitted default and an explicit choice. Schema/default vectors,
scaffold previews, wizard defaults and the public init JSON schema agree.
Explicit `plain` and `herdr` remain supported, with flag/existing origins preserved.
Merely resolving a default does not rewrite manifest bytes. Wizard edits continue
to require normal per-file consent; skipping an omitted setting preserves it.

No remote console session-creation consumer exists. Its future implementation
must consume the effective preference for each new session, including old
manifests omitting the field; existing consoles retain their original backend,
shell and environment. This PR neither creates that API nor verifies runtime
persistence. SC-007 runtime acceptance remains pending that consumer.
