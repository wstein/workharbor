Scope: make the merged stage library reachable through `workspace.stage` and
`ws stage`. This record does not claim promote CLI delivery, T038 completion,
T034 acceptance, real-host verification, or a release.

[tracker #263](https://github.com/wstein/workharbor/issues/263#issuecomment-6403589890).

## Delivered surface

The command table, Cobra flags, default handler, help description and CLI
contracts change together. `--local` is boolean. Stage requires explicit
`--source` and one exact primary name/full ID; resolution remains with the
library. There is no new bare alias. `--smoke` passes directly to preparation.

`--dry-run` prepares and returns the immutable preview, closes temporary
preparation, and never calls Apply. Applying unattended or in JSON mode requires
both `--yes` and the exact preview fingerprint through `--trust`. Interactive
users grant fingerprint trust separately from mutation confirmation; the preview
states the pause-writers condition. Wrong explicit trust refuses with 68;
missing/declined consent is 70. Library effects, home allocation, verification,
recovery and exit mapping are unchanged.

Output retains the schema-version-1 envelope and canonical `workspace.stage`
ID. The closed result includes nullable fields rather than omitting them. Partial
errors retain the library result, recovery identity, original error code/reason
and remediation. No control-plane operation ID is created. All human rendering
escapes untrusted fields. Child diagnostics use stderr, never the JSON stream.

## Reproducible verification

Run from the repository root with `umask 022`:

```sh
go -C apps/whr test ./internal/commands -run '^TestLocalStage' -count=1
go -C apps/whr test ./...
go -C apps/whr vet ./...
python3 -B scripts/check_repo.py
python3 -B -m unittest discover -s tests
git diff --check
```

`TestLocalStageCommandContractAndAlias` checks the registered contract flags,
group alias, default production handler and canonical ID. The transaction tests
use the existing public lifecycle interface: refusal reasons before prepare,
preview versus apply, exact consent fields, close on every prepared path,
interactive acceptance/decline, escaped hostile metadata, preservation of partial
inventory, and library exit-code/error-reason propagation. The schema test refuses
undeclared fields, invalid status/resource kinds, omitted nullable fields, null
arrays and fictional remote operation IDs. These test IDs are required by the CI
acceptance manifest.

The behavioral RED is commit `64b44db5`: the running registry test reports
that the command entry is absent. The fixture correction is folded into that
test commit. Commit `c717924b` specifies the adapter before implementation;
`4b0a272a` demonstrates the permissive old JSON schema. Added error-class
cases characterize the adapter; no historical RED is claimed for them.

Review regressions cover JSON on terminals refusing missing consent before
preparation, nil and empty fingerprints, exact trust and refusal reasons,
supplied trust skipping its prompt, oversized answers, cancellation during an
answer, and case-insensitive, trimmed mutation confirmation. Fingerprint trust
remains exact. Human previews, including dry-run, disclose the pause-writers
condition and the hash limitation. The new preview and confirmation tests
failed before the adapter correction.

Four compile-valid Go overlays check that dropping trust comparison, clearing the
quiescence consent, omitting partial-result attachment, or accepting declined
mutation consent each fails the corresponding focused test. This is bounded
wiring evidence, not exhaustive mutation coverage of the merged libraries.

Linux tests and fake transactions do not establish a real Docker or macOS+
OrbStack journey. The owner-run end-to-end runbook and results remain in the
plan's final documentation package. Native CI and exact-head Opus implementation
review are separate Draft blockers; this record does not self-award CLEAR.
