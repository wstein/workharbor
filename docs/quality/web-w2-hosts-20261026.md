## Behavior and reproducible checks

The page uses `Hosts.list_status/3`, which authorizes `:host_status`, filters the
owner before connection lookup and returns no identity fingerprints, enrollment
codes, certificates or CSRs. Rows have stable ID ordering, default size 25 and
maximum size 50; page numbers stop at 1,000. The exact hosts route accepts only
unique numeric page/size query parameters within 128 bytes. Other route query
admission is unchanged.

A single owner-session timer reauthorizes, refreshes and schedules the next tick
only after completion. The metadata batch has one total one-second deadline;
timeout displays unavailable. A first denial clears rows/principal, stops refresh
and ignores queued ticks without another denial audit. The shared read service
also admits CLI-owner credentials and refuses dashboard credentials. The page
adds no writes or new dependencies. Unknown connection metadata is not proof of
provider health. Existing `HostConnections` tests retain the injected-clock
29,999/30,000-millisecond freshness boundary; W2 separately tests rendering a
changed connected/unknown observation on the next refresh.

The first test-only commit `0d098b5c` produced five semantic failures against
unchanged product code: missing page and missing shared read helper. Subsequent
characterization tests cover the full FR-022 control set, one batch deadline,
queued ticks, changed observations and actual dashboard-kind refusal. They are
not described as preimplementation REDs.
