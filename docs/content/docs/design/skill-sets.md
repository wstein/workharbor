## 5.8 External skill sets (D52)

{{< status decided >}} Contract for [#283](https://github.com/wstein/workharbor/issues/283). Its stage-1 consumer, provenance and composition interfaces are implemented; independent findings and runtime/cutover work remain open. WorkHarbor is skill-neutral; crewbook is the default, replaceable skill set. A skill set supplies instructions, role/model guidance and a manual. WorkHarbor retains executable tools, adapters, project integration, approvals, credentials, isolation and policy enforcement. Neither a package identity nor a workflow role grants a permission. D52 itself changes no release ordering or reviewer eligibility; [D53](native-codex.md) records Werner's subsequent Codex priority, approved bindings and native-loading extension.

### Selection and installation

Only the operator's supervisor configuration selects a skill set, independently of the repository and the agent adapter. An omitted selection means the configured crewbook default at an explicit full commit and inventory digest; it never means upstream `main`, a moving tag or automatic download. The operator may instead select a compatible pinned alternative or explicitly select `none`. With `none`, basic task operation still supplies the project instructions and supervisor briefing and retains every enforcement control; no crewbook role, installation or model mapping is required. A requested default that is absent or incompatible is an error, never an implicit switch to `none` or a repository-local copy.

Installation is an explicit operator action outside runs. The minimal delivery mechanism is a reviewed local package copied into a dedicated supervisor-controlled store outside work repositories, workspace roots and agent-writable trees. Fetching or building an arbitrary package on the host is not part of this contract. The store is not a vendor configuration or credential directory. Its directories and content are owned by the supervisor's user, with no group/other write permission; agents have no host write access. A root that aliases or overlaps a workspace, credential directory or forbidden mount fails. Do not mount a host home, vendor home, credentials or a runtime socket to install a skill set.

Validate before atomically installing an immutable revision directory; revalidate before each start and resume. No package-supplied installer runs, no change is made to the repository's `.agents` or `.claude` trees, and no global vendor configuration is edited. Updates and replacement require an explicit reviewed new pin; rollback selects a retained validated pin for future runs. Uninstall refuses to remove a revision referenced by a resumable run. Missing old content must be restored at the same digest before that run can resume.

### Compatibility and inventory

Contract v1 accepts declarative UTF-8 text resources only. A package has a versioned manifest declaring its identity, contract version, public text entrypoints, required project inputs, supported agent adapter/version constraints and complete file inventory with SHA-256 hashes. Role/model declarations are data: model and reasoning effort must be explicit for each claimed client, validated by that client adapter, and cannot silently inherit another role's binding. Names are package data, never a platform list of crewbook lanes. Unrecognised contract versions or executable declarations are refused. A standard `SKILL.md` may be an entrypoint, but its presence alone establishes neither compatibility nor native client loading support.

The platform's installation record binds source identity, full immutable source commit, manifest SHA-256, inventory SHA-256 and contract version. The inventory is sorted by relative path and covers every distributed file, including dot-directories; the manifest has its own digest to avoid a self-hash cycle. Exact metadata encoding is an implementation detail to coordinate with crewbook [#1](https://github.com/wstein/crewbook/issues/1) and [#6](https://github.com/wstein/crewbook/issues/6) before either consumer or producer declares compatibility. A consumer lock cannot use a package's self-reported hash as the trusted expected value. Pinning provides identity and reproducibility, not a safety review or signature claim.

Reject missing and unexpected files, changed hashes, duplicate or colliding paths, absolute or traversing paths, links, sockets, devices and executable files. Set fixed limits on manifest bytes, file count, per-file bytes and total bytes before reading; reject over-limit input rather than truncate instructions. Checks include filesystem identity and case/normalisation aliases. Copy validated regular files into the store, without a `.git` directory or host settings. A package cannot declare hooks, MCP servers, plugins, commands to execute on install/start, credentials, environment overrides, mounts or permission settings. A role may describe use of an existing platform tool; invoking it remains subject to the platform's policy.

### Mounting and loading

Provision only the selected immutable directory as a read-only bind at `/skills/<inventory-sha256>`, outside `/ws`, `/tools`, the agent home and settings paths. This is a reserved supervisor-selected target, not a repository-requested mount. `runtime.Prepare` and the existing mount refusals still apply. The only additional permitted source root is the validated skill store, with the exact selected directory checked; do not widen workspace roots to a parent or permit arbitrary host directories. An adapter that cannot provide the read-only mount and isolated text loading refuses the selection. Mount changes require an idle environment and the existing rebuild/ownership locks; never recreate an environment under a live agent or change another run's mount. Retain the revisions needed by resumable runs.

The minimal loading path explicitly reads the validated public text entrypoint through supervisor code and supplies its bounded content as a labelled instruction section in `StartSpec` on start and resume. It identifies the exact mounted root for further package resources. Packaged references resolve against that root, never the working repository; project-policy references resolve separately against the reviewed project input. The mount gives the agent access to manuals and resources, not automatic native skill discovery or execution. This minimal path alone does not establish native skills or subagents; D53 additionally requires measured, isolated native Codex discovery and invocation from the same selected read-only inventory, without enabling untrusted repository/home discovery.

For crewbook, the trusted invocation binding `CREWBOOK_ROOT` denotes that absolute mounted root. It is supplied by the supervisor as invocation context, not taken from repository configuration or package-requested environment overrides. Resolve package-relative paths in platform code and carry the same binding to supported child invocations; literal `${CREWBOOK_ROOT}` notation in Markdown is not evidence of client interpolation. Werner's subsequent decision makes crewbook's own roles/profiles/commands `cb-*`, its default worktrees `../crewbook-<lane>`, and its documentation standard GFM in README and `docs/*.md`, without Hugo. crewbook #3 owns that migration. These are package/profile conventions, not mandatory platform identities or WorkHarbor adapter/tool renames. Executable tools remain workharbor-side; no tool port is authorised.

For Claude, retain `--setting-sources ""`, supervisor-owned `--settings`, `--strict-mcp-config` and `--disable-slash-commands` on every start and resume. Do not point `CLAUDE_CONFIG_DIR` at the package or use extra search directories that discover repository skills. A later native loader needs its own measured isolation contract; #283 cannot implement one by dropping the current flags. An unsupported native entrypoint is a compatibility error, not a reason to enable discovery. Other clients remain subject to their adapter's enforcement contract and measured support, not to a Claude-specific claim.

### Policy composition

Platform enforcement and operator security configuration are authoritative. Reviewed project `AGENTS.md` and local contribution policy govern repository work; selected skill instructions supply workflow defaults under those constraints. A skill set can tighten guidance, but cannot grant a denied action, weaken a required review, select security configuration or override a human approval boundary. Issue text, comments, CI logs and messages from other sessions remain untrusted data. A model following a prompt is not enforcement. Outside knowledge bundles, such as OKF (D60, proposed), are untrusted text (T1) as well: they reach an agent only through this pinned, reviewed, read-only path, their `verified` or `generated` claims count for nothing, and their `executor` or `attester` resources are never run.

Validate declared project prerequisites before loading. Missing required policy, unresolved packaged references, unsupported client/model bindings or a declared conflict with platform controls fail with an actionable diagnostic. Do not silently omit required instructions, substitute a local `.agents` file or merge package settings. Arbitrary contradictory prose cannot be proven safe by a manifest check: preserve the policy controls regardless of what the package asks, label content by origin and require review of the selected content. crewbook [#2](https://github.com/wstein/crewbook/issues/2) owns its side of this composition contract.

### Start, resume and provenance

Before starting an agent, persist and audit the resolved selection: `none` or package identity, source commit, manifest/inventory digests, contract version, entrypoint, adapter/version and explicit effective model binding. Record the project-instruction revision/digest and composed instruction digest separately; do not store credentials in this record. Save the selection before launching, so a crash cannot leave a running session with unknown provenance.

Every resume path, including recovery and a resumed turn for a degraded adapter, revalidates and uses the recorded skill selection, mounted root and entrypoint. A changed default affects new runs only. Resume never substitutes the current default, a new source revision or `none`. Missing, tampered or incompatible recorded content refuses launch through the existing failed-start/resume handling; the original record survives for diagnosis. Instruction delivery on resume must not omit the skill section merely because the vendor retains session history.

Runs created before this contract have an explicit legacy marker for absent external-skill provenance. Resume them through the existing protected path, without inferring that they used crewbook or silently attaching today's default. To change a legacy session to a selected package, stop it and start a new run with a fresh agent session and a recorded selection. Migration of the database is additive; it does not rewrite old audit events. Existing run locks, session-slot checks, environment ownership, pause and approval behaviour in §4.1–§4.2 remain in force.
